# Failure modes

What happens when things go wrong, so the code handles each case on purpose. Principle: **never lose expert work, never guess, always tell the expert in plain words what happened and what to do.**

| # | Failure | Detection | Automatic handling | What the expert sees | Owner |
|---|---|---|---|---|---|
| F1 | Upload drops part-way | Missing chunks at `complete` | Resume from the last good chunk | "Your upload paused. It will continue when your connection is back." | Foundation |
| F2 | Uploaded file is not a valid PDF, or is encrypted | Split step fails | Try qpdf repair; if encrypted, stop that document | "We couldn't open *filename*. It may be password-protected. Ask the {instructing_party} for an unlocked copy." Pre-filled 08b request | A |
| F3 | Virus scan flags a file | ClamAV | Quarantine; never processed | "This file was blocked for safety." Audit entry | Foundation |
| F4 | OCR fails on one page | Azure error after 3 tries | Mark page `unreadable`; continue with the rest | Page appears in "Pages we couldn't read" | A |
| F5 | Azure or Bedrock outage or throttling | 429/5xx | The kit first tries the cell's configured in-region overflow models (`BEDROCK_OVERFLOW_MODEL_IDS`, each with its own quota); if all are busy, exponential back-off; job pauses up to 2 hours, then `failed` with a "Try again" button (`POST …/process/retry`, `case.upload`) | Progress shows "Waiting for the reading service, your bundle is safe" | A |
| F6 | Worker crashes mid-job | Job heartbeat stops | Job re-queued without counting an attempt (`jobs.requeued_stall`, migration 0058; a stall is not a failure), but each requeue is counted (`jobs.stall_requeues`, migration 9002) and after `JOB_MAX_STALL_REQUEUES` (default 5) the next stall ends the job `failed` with `stalled_too_often` through the dead-letter path (one `job_dead_lettered` event, kind and id only) instead of putting it back; test: `api/tests/repository/test_foundation_job_stall_cap.py`; idempotent steps skip finished pages. On a stop signal the worker takes no new jobs and, after `WORKER_SHUTDOWN_GRACE_SECONDS` (default 25), pauses running jobs (`resuming`, no attempt) so they carry on at restart (on Railway set the worker service variable `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` to at least the grace plus 5; `railway/worker.json` has no field for it). PDFium and page cutting run off the event loop so the heartbeat keeps beating; test: `api/tests/repository/test_pipeline_worker_loop.py` | Progress continues | Foundation |
| F7 | Model returns invalid JSON or wrong schema | Pydantic validation | One retry; then that page's extraction is marked `needs_human` | Page still readable; "No suggestions for this page" | A |
| F8 | Model cites words that don't contain the value | `provenance.check` | Reject value; one retry; then drop the suggestion | Nothing wrong shown; dropped count logged | A |
| F9 | Prompt injection text in a scanned document ("ignore instructions…") | Output schema plus provenance check (values must be in cited words) | Injected instructions cannot add fields or free text; suspicious pages flagged in metrics | Nothing | A, core |
| F10 | Identifier stripping misses something | Weekly synthetic canary test; log scanner | Block release if the canary fails | Nothing | Core |
| F11 | Cost guard tripped (K3) | Running cost per case | Job paused; alert to you; "Try again" on the paused retry is refused (409 `allowance_used_up`) while the case is still over its allowance | "Taking longer than usual, we're checking it." | Foundation |
| F12 | Date ambiguous (03/04 with no context), two-digit year, or no date on the fact itself | Date normaliser | Unclear dates not guessed; marked "Please check" (`please_check`). A two-digit year gets a century by a fixed rule (`printed_century`); a fact with no date of its own takes the nearest date on its line or the line above (`line_above`); both flagged (ADR 0017) | Badge on the fact; mark on the timeline | A; `api/tests/repository/test_pipeline_date_repair.py` (`printed_century`, `line_above`) |
| F13 | Duplicate wrongly suggested | Expert undo | Undo restores the page | — | A, B |
| F14 | Expert rejects a fact already cited | State machine guard | Warn and list citing paragraphs | "This fact is used in your opinion on Q2. Change it?" | B, E |
| F15 | Two tabs edit the same opinion | `If-Match` version check | 412 `stale` with both versions | "You changed this in another window. Which version do you want to keep?" | E |
| F16 | Report build fails (template problem) | Build job error | Fall back to the standard Avodeck template, flag the template issue | "We couldn't use your template this time; your report is in the standard layout." | F |
| F17 | Session expires while writing | 401 | Autosave every 5 s; draft kept server-side | Sign in again and continue where you were | Foundation, E |
| F18 | Email delivery fails (Resend) | Webhook | Retry; then in-app notice | Today item still appears | Foundation |
| F19 | E-sign webhook never arrives | Timeout check daily | Poll provider; alert after 48 h | "Waiting for Dr X to sign" with a reminder button | I |
| F20 | Deletion job interrupted | Job status | Resumes; certificate only issued when everything is gone | "Deletion in progress" | H |
| F21 | Backup restore needed | Incident | Point-in-time restore runbook (`docs/ops/restore.md`) | Status message | You |
| F22 | Pack file invalid | CI pack-schema check; loader refuses at start-up | Deployment blocked; running cells keep the last good pack | Nothing | Foundation |
| F23 | Model or prompt change lowers accuracy | Nightly eval | Change blocked from release | Nothing | All AI slices |
| F24 | Region model becomes unavailable | Bedrock error | Fail closed (never fall back to another region) | Processing paused message; you choose an in-region replacement | Core |
| F25 | Wrong person's record in the bundle | Pack identifier recognisers disagree with the case subject; expert report | Suggest quarantine; never auto-hide | "Pages 412–415 may belong to someone else. Check and remove them?" | A |
| F26 | Stale write (someone else saved first) | `If-Match` ETag mismatch | 412; nothing overwritten | "This changed in another window. Which version do you want to keep?" | Foundation, all |
| F27 | Repeated request (double click, retry after timeout) | Same `Idempotency-Key` | Return the first result | Nothing (one invoice, one serving) | Foundation |
| F28 | Scheduled job missed (deploy, outage) | Run key for that date absent | Next run catches up each missed date once | Reminders arrive late, never twice | Foundation |
| F29 | Backup restored after deletions | Restore runbook step | Replay `deletion_ledger` before reopening (`select app.replay_deletion_ledger()`, operators only: removes each case again and destroys its key again) | Nothing | Foundation (ledger, replay); H (runbook) |
| F30 | Deletion due while a legal hold is active | Hold check in deletion job | Skip the case; notify | "Deletion paused: legal hold until …" | H |
| F31 | Named expert leaves the organisation | Membership ended | Keep named-case access; remove all other access | Their Today shows only their named cases from that organisation | O |
| F32 | Last owner tries to leave | Membership guard | 409 | "Make someone else an owner first." | O |
| F33 | Email bounces | Resend webhook | Mark address; stop emails; in-app banner | "We couldn't email you. Check your address." | Foundation |
| F34 | Pack correction marked mandatory | Pack version change | Block signing on unserved cases until acknowledged | "The court wording has been corrected. Please review before signing." | Foundation, F |
| F35 | Court bundle re-issued after the trial pack was built | New court bundle version | Mark trial pack and offline packages stale | "New court bundle received; rebuild your trial pack." | I |
| F36 | Non-PDF file uploaded (email, image, Word, audio) | File type sniffing | Convert to pages; audio, video and imaging become exhibits | "This recording is stored but Avodeck can't read it." | A |
| F37 | Foreign-language page | Language detection | Flag; no machine translation | "This page isn't in English. Ask for a certified translation?" (language from the pack) | A |
| F38 | Support needs to see a case | Support request | Metadata only unless the named expert grants access | Grant shown on the case and in its audit trail | O |
| F39 | Someone guesses or replays authenticator codes | `mfa_attempts` | 5 wrong codes in 15 minutes lock MFA (429) on every device; a code already accepted is refused; a recovery code signs out every other device | "Too many tries. Wait 15 minutes and try again." | Foundation |
| F40 | A stored file part is missing, moved or changed | Chunk sealed to its own path; whole-file SHA-256 re-checked while downloading | Download stops with an error; never sends a different file | "We couldn't open this file. Please contact support." | Foundation |
| F41 | A risky action from a session with no code yet (sign-in is password only, ADR 0025) | 403 `mfa_required` with `mfa_enrolled` | Nothing is done; the web app asks for the code, or sets the authenticator up and shows the backup codes once, then sends the action again; cancelling changes nothing | "Set up the code on your phone" or "Please enter your code"; on cancel "Nothing was changed. You need your security code to do this." | Foundation |
| F42 | A part of an upload is damaged on the way, or sent without its checksum | Every part carries `X-Chunk-SHA256`; the server hashes the bytes it received and compares in constant time (422 `chunk_corrupted`; 422 `chunk_sha_missing` when absent or not 64 hex characters) | The part is not stored and `received` does not change; the web app sends it again, hashing the same slice again, up to 3 more times | Only if it still fails: "Part of this file didn't arrive properly. Please add it again." | A |
| F43 | The stored file is not the file that was sent (for example a part sent under the wrong number) | `complete` carries the whole file's SHA-256 (422 `file_sha_missing` when absent or malformed; 422 `file_hash_mismatch` before any Storage read when it differs from the hash given at start). It claims the upload as `finalizing` and returns 202; the `finalize_upload` worker job re-reads the stored parts in order, decrypting one at a time into one running hash, and checks each part against the hash kept when it arrived and the byte count. Parts and complete take one per-upload lock, so a part cannot land mid-claim and two completes give one job and one document; a repeat complete after success returns the document, and one carrying a different hash is 409 `file_hash_mismatch` | A whole-file hash mismatch (`sha256_mismatch`), size mismatch (`size_mismatch`) or a damaged part (`chunk_unreadable`) closes the upload as `failed`; no document is made and it can never be completed; its parts are removed by the daily sweep; ids and counts are logged, never contents | "This file didn't check out after it was added, so we haven't kept it. Please add it again from the start." | A |
| F44 | A stored part is missing when the `finalize_upload` job reads it (never arrived, or removed) | The job lists the upload's parts and finds a gap | The upload is reopened with the missing parts forgotten (`upload.chunk_missing` audited, naming the upload only, no person; the part number is in the log); the client sends only those parts and completes again | "Part of your file didn't arrive. We'll send the missing part again." | A |
| F45 | Storage cannot be reached while the job reads the parts | Storage error other than not found | The job fails and is retried with back-off up to its attempt limit; the upload stays `finalizing` and a repeat complete with a failed job re-claims it with a fresh job; the sweep expires it past `expires_at` | "We're still checking your file. It will finish shortly." | A |
| F46 | The expert cancels an upload (or the page is closed) | `POST /v1/uploads/{upload_id}/cancel` by someone holding `case.upload` | Allowed only while `open` (409 `upload_closed` once `finalizing` or later); parts are deleted by the daily sweep | "Upload cancelled." | A |
| F47 | A case is put on hold while an upload is being checked | The `finalize_upload` job waits like any processing job (`case_on_hold`, queued) | The upload stays `finalizing` until the case resumes; if the hold outlasts `expires_at`, the daily sweep expires it whatever the job's state but running, and removes its parts (migration 0125); nothing is registered meanwhile | "We'll finish adding your file when the case is back in use." | A |
| F48 | Extraction runs cleanly (valid schema, values all in their cited words) but covers little or nothing of a page with real writing on it | `coverage.reason_for`: enough countable words, but no kept facts (`no_facts`) or under half the page's words covered by kept facts/entries (`low_coverage`) | Page marked `needs_human` with that reason, same as F7/F8; never overrides a reason already set by OCR or the words check. A page with enough words whose entries cover under 80% of them (`coverage.entry_reason`, `low_entry_coverage`) is asked once more; the second answer replaces the first only when it covers strictly more, and the page is never marked for a person for this alone | Page still readable; "No suggestions for this page" | A |
| F49 | PDF build too large or slow (many pages, large pictures) | The download screen polls the `export_transcript_pdf` job and finds it still running | The job keeps running and finishes later; the file is still handed over once, through the same download route | The slow-build message on the download screen; the file arrives later | B |
| F50 | A page picture is missing from storage when the PDF build reads it | Storage has no picture for that page (not found) | That page's picture is replaced by "Picture not available" and the build continues with the other pages; test: `test_the_pdf_job_gets_a_picture_per_page_and_goes_on_without_a_missing_one` in `api/tests/repository/test_reader_transcript_job.py` | "Picture not available" at that page in the PDF | B |
| F51 | The hosted session pooler refuses the worker's connections (`EMAXCONNSESSION`: more clients than its pool size) | The worker's two pools (`WORKER_DB_POOL_MAX` default 10, `WORKER_QUEUE_POOL_MAX` default 4) add up to more than the pooler's pool size (15 by default) | The defaults fit inside 15 for one worker replica; model calls in flight follow the worker's pool less a reserve of two (about 8 at once by default, on 10 + 4 connections per replica); a second replica, the `worker-interactive` service (6 + 4 connections; budget table in `docs/runbooks/railway.md`) or any other client on the same pooler role needs more pooler capacity (raise the Supabase pool size first, then `WORKER_DB_POOL_MAX` / `WORKER_QUEUE_POOL_MAX`); the pooler's pool size is documented next to the variables (`api/.env.example`, `docs/runbooks/railway.md`); a size that is not a positive whole number stops the worker at start, naming the variable; test: `api/tests/unit/test_foundation_worker_pools.py` and `api/tests/repository/test_pipeline_kit_limits.py` | Nothing (an operator matter); jobs keep running | A, Foundation |
| F52 | A job's database connection drops while the worker records how the job ended ("SSL connection has been closed unexpectedly") | `psycopg.OperationalError` in the status write; later, a `running` job with no queue row waiting or held (todo/doing) | The write is tried again on a fresh connection a few times with short waits (`DEFAULT_PERSIST_WAITS`); if all fail, `JobWorker.requeue_orphaned()` (at worker start and every housekeeping round; `app.requeue_orphaned_jobs()`, migration 0134) moves it running -> failed -> queued with a new queue row while attempts remain, else running -> failed (`job_error`); a write that committed before the drop is not done twice (each step names the status it moves from), and a `queued` job left with no queue row (and not tagged `case_on_hold`) is given a new one, status unchanged (migration 0135); test: `api/tests/repository/test_pipeline_job_connection_loss.py` | Progress carries on, or the usual "Try again" shows if the job ran out of attempts | A, Foundation |
