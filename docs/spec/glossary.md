# Plain-language glossary

Use these words in the interface. Users are GPs aged roughly 50–60 who are not confident with computers.

| Say this | Not this |
|---|---|
| Pages you've read | Coverage, read progress |
| Pages we couldn't read | OCR failures, low-confidence pages |
| What we found on this page | Extracted entities, AI suggestions |
| Checked by you | Verified |
| Please check | Unverified, pending review |
| Not right | Rejected, false positive |
| Thing to look at | Anomaly, flag, alert |
| As the clinician saw it on… (the pack shows the clinician's role, e.g. "As the GP saw it on…") | Temporal filter, point-in-time view |
| Points against | Counter-arguments, adverse facts |
| What other GPs might reasonably do | Range of reasonable practice (in headings) |
| Read first, then see our suggestions | Blind read |
| Trial page numbers | Concordance, re-pagination |
| Final check | Validation, compliance check |
| Your report has been served | Report submitted, finalised |
| Something went wrong. Your work is saved. | Error 500, exception |
| The named expert / you're the expert on this case | Case owner, assignee |
| Who is this case for? (your practice or a team) | Organisation, tenant, workspace |
| People, role | Members, membership, RBAC |
| Not this patient's record / set aside | Quarantine, misfiled, wrong-patient flag |
| Clearer copy | Superseded page, replacement |
| Delivery (first delivery, second delivery) | Bundle version |
| Recording or image Avodeck can't read | Exhibit, unsupported media |
| Supplementary report | Addendum (except where the pack uses it) |
| Earlier versions | Revision history, opinion_versions |
| First set of questions, second set | Round |
| Court order | Direction (where the pack uses it) |
| Pause deletion | Legal hold |
| On hold | Stayed, suspended |
| Backup codes | MFA recovery codes |
| Where you're signed in | Sessions, devices |
| Records custodian | Successor, delegate |
| Your trial pack needs rebuilding | Stale artefact |

**Rules:** short sentences; one main action per screen; say what happens next; never blame the user; no technical codes on screen.
