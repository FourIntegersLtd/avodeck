# 0030 Vision with masking (T-10 second reading)

Date: 2026-10-31 · Status: accepted · Decided by: the founder (plan "lazy-mapping-waterfall", item 6) · Builds on: rules 1, 2, 6 and 7, ADR 0028

**Problem.** Some pages are handwriting the computer cannot read. The expert types them out, and wants a second pair of eyes that copies the writing. Only the picture will do, and a picture can show a name or number that no text step can strip.

**Decision.**
- **The picture is masked before it can leave.** `core/ai/mask.py` paints a black box (the word's polygon plus a margin) over every OCR word that touches an identifier span (`pii.spans`: the same choice as `pii.strip`, as character ranges). Only a `MaskedImage`, built by `mask_page`, can be given to `AiKit.run_image`; raw bytes are refused.
- **Fail closed.** `MaskUnsafe` is raised, and the request is refused with a reason code, when there are no words, the page reads too poorly (mean confidence under 0.35), the picture is not the size the OCR frame implies, an identifier span has no word, nothing at all was masked, or a touched word has no place on the page. Nothing is sent and the reason (a code, never text) is stored.
- **Doubtful words, corrected runs and unmatched typing also fail closed (review of PR 172).** A word the expert corrected is painted along its whole run of boxes, not just the first. A word read below confidence 0.5 refuses the request (`doubtful_word`) when it nearly spells a name token (tokens under 3 letters match exactly only; 3 to 5 letters allow one change, longer ones two; from 4 letters the same first letter and a length within 1 also counts when the changes are at most half), looks like a full date, is mostly digits (or O, l, I read for digits) with three or more of them, or is a month name read one letter wrong next to digits. A run of neighbouring doubtful words with digits refuses when it holds six digits or matches the pack's identifier formats. OCR may have misspelt an identifier that no span could find; ordinary handwritten words are not refused. A name or date of birth found in the expert's own text more often than in the fresh reading's boxes (counted per identifier, so a surname typed in a header and a footer needs two boxes) refuses it (`identifier_unmatched`). The request remembers the page's turn when it was asked; if the turn differs when the job runs, or the stored picture is not the one asked about (its sealed bytes' hash is kept too), or a page job for the case is still queued, running or paused or the newest one failed, it refuses (`page_changed`). Slice A does not store which turn a picture was drawn at, so this is the proof available without reading its tables because a half turn passes the picture-shape check. `MaskedImage` carries a per-process seal bound to the picture's hash, checked on creation (so `dataclasses.replace` cannot swap the picture) and again in `run_image` (hash and seal, constant-time).
- **Expert-typed pages are read again for boxes.** The typed words have no place on the picture, so the job runs OCR on the page again and masks from those boxes; if that is not possible the request is refused (`no_place`).
- **PNG, not JPEG.** The masked picture is lossless, so black stays exactly black and the guard test can check pixels. Its SHA-256 is recorded with the request; the bytes never are (rule 6).
- **Never opinion, never a fact.** T-10 copies the writing, line by line, with a confidence. Its lines are stored sealed in `second_readings`, shown beside the page, and never written into the expert's text or turned into facts (rules 1 and 2). Only the named expert and their assistant may ask (`page.transcribe`).
- **`GET` stays as it is, and why.** `GET /cases/{id}/pages/{n}/second-reading` returns the model's copy of the handwriting, not facts or suggestions, so the blind read of rule 3 (423 until the page is marked read) does not apply to it: it carries nothing the expert has not been shown by the picture. It must work when the expert cannot read the page at all (that is the point of the feature), and it needs `page.transcribe`, the same permission as typing the page out. The lines are never merged into the expert's text and never become facts (rules 1 and 2).
- **A failed job is shown.** A request that raises anything unexpected is marked `failed` with the reason `unexpected_error` (the exception type is logged, never its message); the panel shows the failure, and asking again resets it. A job writes its outcome only for the request it read (`requested_at`), so a newer request is never overwritten by an older job.
- **In region.** The picture goes only to Bedrock London, in-region model IDs (rule 5).

**Rejected.** Sending the picture and trusting the model to ignore names (breaks rule 7). Blurring (can be reversed). Masking by the word's box alone with no confidence floor (the box of a badly read word is a guess).
