# Spikes: prove the risky assumptions before the foundation slice

A spike is a short, throwaway experiment that answers one question. Code lives in `spikes/<n>-<name>/` on a branch that is **never merged**. Only the written result is kept, appended to this file, plus a decision record if the plan changes.

Run spikes 1–4 and 8 before foundation **stage 2** (the cloud parts); foundation stage 1 runs locally and doesn't wait for them. Run 6 and 7 during stage 1 on the born-digital pages, and again with Azure OCR in stage 2. Run spike 5 at the end of slice A, on the real pipeline in staging (5a gives an early estimate before that).

**Data rule:** synthetic data only (the Mrs A bundle in `evals/`). No real records in any spike.
